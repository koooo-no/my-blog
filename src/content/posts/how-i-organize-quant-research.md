做量化研究最大的风险不是策略亏钱，是**你自己骗自己**。

半年后回头看一份报告，你已经忘了当时的语境。你只会记得那个漂亮的年化收益，不记得它是在试了 60 个变体之后挑出来的。

这套目录结构不是为了好看，是为了**对抗这件事**。

---

## 整体结构

```
A_stock_quant/
├── config/settings.py      全局参数（费率、风控、优化网格）
├── data/                   数据层
│   ├── fetcher.py          下载 / 增量更新 / 前复权 / 离线降级
│   ├── market.db           行情库（SQLite，1.4 GB）
│   └── universe.py         股票池筛选
├── database/db.py          SQLite 访问层
├── indicators/             技术指标
├── factors/                因子计算
├── strategies/             策略定义
├── backtest/               回测引擎（T+1 / 涨跌停 / 费用 / 防未来函数）
├── risk/                   风控
├── trading/                模拟账户、每日扫描
├── evaluation/             评估：基准、IC 分析、组合引擎、报告生成
├── baseline/               ★ 冻结基线
├── output/                 ★ 正式产物（报告、结果 JSON）
├── temp/                   中间过程（可以随便删）
├── tests/                  自动化自检
├── ui/                     Streamlit 本地界面
└── logs/
```

整个项目 **38 GB**，`market.db` 占 1.4 GB。纯本地，不接券商、不存 API Key、不做真实下单。

## 三个关键设计

### 一、`output/` 和 `temp/` 必须分开

这是最重要的一条。

| 目录 | 含义 | 可以删吗 |
| --- | --- | --- |
| `output/` | 正式结论 | **不可以** |
| `temp/` | 探索过程 | 随便删 |

`temp/` 里堆着几百个中间文件：各种参数组合的净值、失败尝试、一次性分析。这些是**过程**，不是结论。

分开的好处是：半年后你打开 `output/`，看到的都是当时认为值得留下的东西；不需要在一堆 `test_final_v2_real.csv` 里找哪个才是真的。

### 二、冻结基线：把"当前认为最好的"钉死

`baseline/<基线代号>/` 里存的不是最新代码，是 **一个被冻结的版本**：

```
baseline/<基线代号>/
├── MANIFEST.sha256          所有文件的哈希清单
├── config/                  冻结时的配置快照
├── code/                    冻结时的策略代码
└── results/                 冻结时的结果
    ├── reference_metrics.json     ★ 权威指标
    ├── equity_curve.csv           净值曲线
    └── yearly_returns.csv         分年度收益
```

**冻结的意思是：这个版本的参数不再因为任何一段的表现而调整。**

这解决了一个很实际的问题：如果你的策略每天都在被微调，你永远不知道当前这条曲线是"策略本身"还是"最近一次微调的效果"。

有了冻结基线，后续所有的比较都有了固定的参照物 —— 新想法的表现，永远是相对**同一个**基线来评估的。

`MANIFEST.sha256` 是配套的：任何文件被改动过，哈希就对不上。这防的是"不知不觉改了基线还不自知"。

### 三、预注册：跑之前先写下要跑什么

做参数敏感性测试之前，先把这次要跑的**所有组合**登记到一个 JSON 里锁起来，然后才开跑。

```
temp/phase8/p8_preregister.json
  → 锁定 106 个主注册运行 + 18 个敏感性运行
  → 登记所有输入文件的 sha256
  → 跑完 GATE 校核
```

听起来很形式主义，但它挡住的正是最危险的操作：**看到结果不好，回去改一下再跑**。

跑完之后想改？可以，但那是一次**新的**实验，需要在报告里说明。

## 报告里的固定段落

每份正式报告都有固定的开场，写清楚四件事：

> **纪律**
> 本批未修改任何策略参数，未做任何事后优化，未接入任何下单通道。
>
> **数据区间**
> TRAIN 2020-01-01~2022-12-31 / VAL_2023 / VAL_2024 / TEST 2025-01-01~2026-09-09
>
> **可复现性**
> 全部输入文件 sha256 登记于 `p8_preregister.json`
>
> **真实下单**
> 未接入任何下单通道，全部为离线模拟

这几行不是客套。**写下来之后，你就很难在后面的段落里偷偷放宽标准了。**

## 自动化自检

`tests/` 下有个防未来函数测试，跑一次几分钟，逐项输出 PASS/FAIL：

```
[PASS] 指标因果性（多个时间点截断对比）
[PASS] 信号日 < 执行日
[PASS] 截断回测无越界成交
[PASS] 停牌日不成交
[PASS] 涨跌停不可成交（分板块阈值）
[PASS] 数据无重复日期 / 升序 / 无 NaN
```

关键不在于测试写得多全，而在于**它会一直跑**。今天没有泄漏，不代表改了因子逻辑之后还没有。

具体是怎么测的，我单独写了一篇：[回测里的未来函数藏在哪](/notes/look-ahead-bias)。

## 做对之后得到什么

这套东西没有让策略收益变高。**它让收益数字变低了** —— 因为各种乐观假设被逐个拆掉。

但它换来了一样更值钱的东西：

> **你知道自己的数字是怎么来的，也知道它在什么条件下不成立。**

比如现在我能明确说出这条基线的边界：

- 全样本年化只有**个位数**，最大回撤**接近腰斩**（不是测试段的那个漂亮数字）
- 硬容量上限在**千万元量级**，超过这个规模单子就下不进去
- 把成本假设放大到 3 倍、再加 0.2% 滑点，测试段年化会被**吃掉一半左右**
- 主要已知偏差：股票池用当前成分回溯，存在幸存者偏差

这些结论**不好听**，但它们是可信的。而一套你不敢全信的漂亮数字，其实没有价值。

---

## 几条经验

1. **过程产物和结论产物分开放。** 半年后你会感谢自己。
2. **冻结一个基线，然后永远拿它做参照。** 不要让参照物跟着最新想法漂移。
3. **跑之前先登记。** 写下要跑什么、评估标准是什么，再开跑。
4. **报告写清局限。** 尤其是幸存者偏差这类方向已知、幅度未知的问题。
5. **自检自动化。** 靠人记得住的纪律，都不是纪律。
