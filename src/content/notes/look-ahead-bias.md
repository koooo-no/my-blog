## 为什么单独写一篇

未来函数（look-ahead bias）最麻烦的地方在于：**它不会报错。**

代码跑得通，曲线很漂亮，回撤很低 —— 你只会觉得策略不错。等到真金白银跑起来，收益凭空少一截，而且很难定位。

我自己的项目里专门写了一个自动化测试来盯这件事。这篇记录五类最常见、也最容易漏掉的泄漏。

---

## 五类泄漏

### 一、用当天的信息做当天的交易

最经典的一种。收盘后算出信号，然后按**当天收盘价**成交。

问题很明显：你不可能在收盘的同一时刻既知道收盘价、又完成成交。

**做法**：信号和执行错开一天（T+1）。在代码里把它写成不变量 —— 卖出信号的日期必须**严格小于**成交日期。这可以断言，不需要靠人记得。

### 二、指标计算碰了未来数据

`rolling` 和 `ewm` 用得不对，很容易越界。典型场景：

- 用了 `center=True` 的滚动窗口（窗口居中 = 用到未来）
- 先对全序列做标准化/归一化，再切分回测
- 用整个样本的均值方差做 z-score

**做法**：**截断一致性测试**。

```
在多个时间点 i 上，验证：
  enrich(df[:i+1]).iloc[-1]  ==  enrich(df).iloc[i]
```

也就是"只用前 i 行的数据算出的指标"必须和"用全序列算出来的第 i 行"完全相等。

如果指标偷看了未来，两者就会不一致。这个测试能一次性覆盖几十个指标，比人肉审代码可靠得多。

### 三、用截断数据回测，却有越界成交

把 `df[:k]` 喂给回测引擎，如果引擎内部读了 `df` 的全长，就会产生**日期晚于 `dates[k-1]` 的成交**。

**做法**：跑一次截断回测，断言所有成交和净值日期都不超过截断边界。这条比第一条更强，因为它能抓住引擎内部的索引错误。

### 四、股票池用了当前成分

这一条最隐蔽，也最容易被"技术性忽略"。

你今天的股票池是**今天**的成分股。用它回溯 2020 年，等于假设自己六年前就知道哪些股票能活到今天 —— 那些退市的、被 ST 的、暴雷的，全都不在样本里。

**方向是确定的：这会系统性高估收益。** 幅度未知，取决于股票池的换手率。

完全消除很难（需要历史成分数据）。能做到的是：**在报告里写明这一点**，并且不要把它当成小事。我的研究笔记里专门留了一条局限性写这个。

### 五、涨跌停和停牌没处理

- 涨停时你买不进，但回测按涨停价成交了
- 跌停时你卖不出，但回测顺利卖出
- 停牌（成交量 = 0）的股票根本不该成交

**做法**：引擎层面直接拦掉 —— 涨停不买、跌停不卖、成交量 0 的日期不执行挂单。顺便记住涨跌停幅度是分板块的（创业板/科创板 20%，主板 10%）。

## 数据质量是地基

上面这些都建立在数据本身没问题的基础上。跑回测前至少要检查：

- 日期无重复
- 日期严格升序
- 收盘价无 NaN、无 0、无负值
- 复权方式一致（前复权混后复权 = 凭空造出收益）

这些检查很便宜，但跳过任何一条，后面所有结论都不成立。

## 怎么把它变成自动化的

人肉审查靠不住，尤其是隔了几个月回来看自己的代码。我把上面这些做成了一个自检脚本，跑一次几分钟，输出逐项 PASS/FAIL：

```
[PASS] 指标因果性（多个时间点截断对比）
[PASS] 信号日 < 执行日
[PASS] 截断回测无越界成交
[PASS] 停牌日不成交
[PASS] 涨跌停不可成交
[PASS] 数据无重复日期 / 升序 / 无 NaN
```

**关键不是测试写得多全，而是它会一直跑。** 今天没有泄漏，不代表三个月后改了因子逻辑还是没有。

---

## 一条经验

> 如果一份回测结果好得超出预期，**先假设有泄漏**，而不是先假设找到了 alpha。

大多数时候你是对的。剩下那小部分，才是真正值得投入时间的。
