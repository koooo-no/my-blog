> 本文为成本模型的离线测算，不含任何持仓明细。
> 具体筛选阈值与因子构造不在此披露。

## 研究假设

**「加了流动性约束之后，成本随资金规模怎么变？容量边界在哪？」**

一个常见的直觉是"钱越少成本越低" —— 冲击成本确实随规模下降，但**固定费用随规模上升**
（单笔最低佣金摊在更小的仓位上）。两者方向相反，所以总成本应该存在一个**最低点**，
而不是单调的。

这个假设可以证伪：如果成本随资金单调下降，说明固定费用项可以忽略，"小资金成本更低"成立。

## 数据来源

- 数据源：本地行情库（A 股日线），成本模型基于个股 20 日平均成交额与日波动
- 标定区间：TRAIN 段（2020-01 ~ 2022-12）—— 分层阈值**只由这一段产生**
- 评估区间：TEST 段（2025-01 ~ 2026-09），只评估一次
- 基准资金：100 万元（用于分层成本对照）
- 交易约束：T+1；涨停不买、跌停不卖；停牌日不成交

**所有用于分层的参数都取自 TRAIN 段**，TEST 段仅用于评估，运行前后未做参数回调。

## 方法与参数

单边成本拆成三项：

```
单边成本 = 价差项（按流动性档位取若干个最小报价单位，设下限）
         + 冲击项（与个股波动率、委托占比的平方根成正比）
         + 费率项（佣金 + 印花税，含最低佣金门槛）
```

关键在**分层**：把股票按 20 日平均成交额（adv20）切五档，
成交额最低的档位成本最高。委托占比定义为「委托金额 / adv20」，同样是 trailing 口径，不含未来信息。

这样做而不是用一个统一的固定滑点，是因为**成本对成交额是非线性的** ——
用平均值会把结构性差异抹平。

## 回测结果

### 一、五档单边成本（100 万资金）

| 流动性档位 | 单边成本 |
| --- | --- |
| T1（成交额最低） | **29.51 bp** |
| T2 | 21.22 bp |
| T3 | 16.04 bp |
| T4 | 10.99 bp |
| T5（成交额最高） | **5.93 bp** |

**最差档是最优档的 4.98 倍。** 这不是渐变，是陡的。

按实际成交金额加权后：

| 指标 | 数值 |
| --- | --- |
| 加权滑点 | 17.88 bp |
| **加权单边总成本（含费）** | **26.283 bp** |
| 成交金额落在最低两档的比例 | **43.3%** |
| 成交金额落在最高两档的比例 | 27.1% |

**43.3% 的成交金额发生在最差的两档上** —— 这是加权成本被拉到 26bp 的主要原因。
换句话说，这条策略的交易有相当一部分落在流动性较差的位置，约束降低了这部分暴露，
但没能消除它。

### 二、成本随资金规模的变化（关键发现）

| 资金 | 单边成本 | 其中费率 | 其中滑点 | 单笔最大占比 | TEST 收益 |
| --- | --- | --- | --- | --- | --- |
| 10 万 | **41.90 bp** | 27.95 bp | 13.94 bp | 0.14% | +24.84% |
| **50 万** | **25.59 bp** | 9.49 bp | 16.10 bp | 0.72% | **+33.57%** |
| 100 万 | 26.28 bp | 8.40 bp | 17.88 bp | 1.44% | +33.14% |
| 500 万 | 32.77 bp | 7.60 bp | 25.16 bp | 7.06% | +29.96% |
| 1000 万 | **37.86 bp** | 7.51 bp | 30.34 bp | **13.89%** | +27.68% |

**成本是 U 型的，最低点在 50 万附近。**

- **规模太小时，费率项吃人**：10 万资金下费率高达 27.95 bp —— 因为单笔最低佣金
  摊在很小的仓位上。相比 100 万，同样一笔交易多付 3 倍多的费率。
- **规模太大时，冲击项吃人**：1000 万资金下滑点涨到 30.34 bp，
  单笔委托最大占到个股当日成交额的 13.89%。相比 100 万，滑点几乎翻倍。

**所以"小资金成本低"是错的，至少对这条策略不成立。**
最优区间在 50 万 ~ 100 万，两端都会变差。

TEST 收益那一列也印证了同样的形状：50 万最高（+33.57%），
10 万掉到 +24.84%，1000 万掉到 +27.68%。

### 三、成本临界点

| 指标 | 数值 |
| --- | --- |
| 现实基线成本（100 万，分层加权） | 26.283 bp |
| 全样本绝对收益归零 | 单边 **53 bp** |
| TEST 段绝对收益归零 | 单边 **79 bp** |
| 相对现实基线的缓冲 | 全样本约 **2.0 倍**，TEST 约 **3.0 倍** |

也就是说，**成本假设要比现实基线恶化 2~3 倍，这条策略才会归零**。
这个缓冲不算厚，但也不是一碰就碎。

## 成本与风险

- **对成本假设的敏感度**：约 26bp 的现实基线对应 53bp 的归零点，
  意味着成本估算每高估/低估 10bp，收益预期就要相应调整 —— 而 10bp 的误差在成本建模里很常见
- **容量硬上限**：1000 万资金时单笔最大占比已达 13.89%，接近约束上限。
  继续放大资金，会出现「部分委托进不去」的情况，实际持仓偏离设计意图
- **成交失败主要来自涨跌停**：在所有测试的资金档位上，因容量被拦下的委托都是 **0 笔**，
  因涨跌停被拦下的有 28 笔。成交率稳定在 99.65% 左右
- **涨跌停拦截无法通过调小资金解决** —— 它和规模无关，小资金一样会遇到
- **区间风险**：成本模型参数为工程设定，不是用真实成交回报标定的

## 局限性

1. **成本模型是估算，不是实测。** 价差项与冲击项的系数为工程设定，没有用真实成交回报做标定。这是本文最大的不确定性来源。
2. **分层阈值只由 TRAIN 段产生。** 这避免了前视偏差，但如果 TRAIN 段的流动性结构不代表未来，分层就会系统性偏离。
3. **未建模拆单与多日建仓。** 现实中可以把大单拆成小单分散到多日，本文按单日完成处理，因此**高估**了大资金的成本。
4. **未建模部分成交。** 假设委托要么全成要么不成，实际存在部分成交与排队。
5. **容量上限是"首个委托触限"的位置**，不是"策略失效"的位置。真正的可用边界要更保守。
6. **本文只测算 B3**，不与任何其他版本做横向比较。

## 后续计划

- **用真实成交回报标定成本系数**，替换目前的工程设定 —— 这是提升可信度的第一优先级
- **建模拆单**：把大单拆分到多日执行，重新测算 500 万以上的成本曲线
- **细化可用规模建议**：目前只能给出 50 万 ~ 100 万为成本最优区间，
  需要结合"能承受多厚的成本缓冲"给出更具体的建议
- **持续用前瞻跟踪的实际滑点对照模型预测** —— 模型说得对不对，实盘前向数据会验证
